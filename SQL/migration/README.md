## Protected inspection core — local, partial P4-03b

`protected-reader.cjs` exports `encodeInspectionSource(records, targets, key)` and async `openInspectionSource(absolutePath, key)`. The caller supplies a private 32-byte Buffer key; the encoder returns encrypted bytes, never writes a file or persists the key. The reader returns a session with `page({checkpointPath, limit})`, `checkpoint(page, results)` (encrypted bytes only) and async `saveCheckpoint(page, results, absoluteDestination)` (durable exclusive publication). Page limits are 1–500 (default 100); the complete encrypted snapshot is bounded to 8 MiB and 10,000 records in memory, not streamed without limit. No real-data CLI/exporter is enabled.

Artifacts use randomized AES-256-GCM, purpose-separated keys and keyed content digests. Source records, supplied target snapshots and the local migration/helper/schema/connector revision are bound to each inspection checkpoint. Unknown business fields remain in the private envelope, absent and NULL remain distinct, and unsafe/lossy JSON values reject. Credentials and integrations/OAuth-state categories reject rather than being silently discarded: their producer must inventory and retain them separately under the existing integration security policy. Successful decoding does not approve domain values or declare a target census complete.

Files must be outside the repository, regular/non-symlink/single-link, process-owned and mode 0600, in an owned real-path directory of mode 0700. Reads are bounded and fail closed with fixed errors. This requires POSIX ownership/mode support. Key custody remains external; no KMS/dependency/paid service is introduced. Same-owner hostile processes or a compromised key holder are outside this protection. Encryption authenticates bytes under the supplied key, not independent production provenance or a tested backup.

Each checkpoint requires one ordered `{index, disposition, reasons}` decision for every page record. Dispositions are only blocked/rejected/excluded; reasons are bounded fixed-code strings, never patient text. Version-2 checkpoints carry every earlier decision from index zero plus the current page, with private per-record identity/content digests. Resume verifies the full contiguous prefix and source/target/code binding, including across changed page sizes and reopened sessions. Version-1 checkpoints are rejected; re-inspect from the retained source, never bypass revision checks or translate an old artifact into apply permission. Returned records, targets, tokens and artifact bytes are PRIVATE: never log them. `done` means end-of-input only; applied remains zero and readyForApply remains false.

`saveCheckpoint` writes encrypted bytes to an exclusive random 0600 sibling temporary file, syncs/closes it, publishes with an exclusive hard link, removes the temporary name, then syncs the directory. Existing files/symlinks/concurrent winners are never overwritten. Use a new destination per page and retain the preceding verified checkpoint; no mutable latest-pointer is provided. Before-publication failures yield INSPECTION_CHECKPOINT_WRITE_REJECTED. After-publication failures yield INSPECTION_CHECKPOINT_WRITE_UNCERTAIN: the destination may exist, so do not overwrite/delete it or assume durability. A crash before temporary-link removal can leave two links and the reader will reject it; stop for private operator recovery, not automatic deletion. Durability relies on a local POSIX filesystem honoring file/directory fsync; network filesystems and actual power-loss behavior have not been certified. Tests inject both sync failure boundaries but do not cut physical power.

### Validator-coupled inspection

Prefer async `session.inspectAndSave({destination, checkpointPath?, limit?})` for the protected inspection pipeline. Omit unused options (explicit undefined values are rejected). It accepts no decisions/callbacks/target overrides: the session uses its decrypted immutable source/targets and existing pure validators. It runs known catalogue, patient/ownership, booking config, schedule, appointment/event, clinical, feedback/audit and counter/request checks, including exact timestamp preparation for mapped candidates. All dependencies use the whole bounded batch, not just the current page. Unknown fields/sources and invalid values remain rejected and retained privately, never silently dropped. Other recognized categories retain their existing excluded/deferred disposition; Auth remains authoritative and exclusions do not mean permission to delete source evidence.

Every resumed prefix is recomputed with current validators and compared to the stored decisions before advancement, including at end-of-input. A low-level caller-authored checkpoint with differing decisions is rejected. A matching caller-authored checkpoint is equivalent inspected input, not independent proof about its author. The low-level page/checkpoint/saveCheckpoint APIs still permit caller decisions and must not be advertised as validator execution proofs. The code fingerprint prevents resuming after a source revision changes; reinspection, not bypass, is required.

The returned report contains current-page counts and fixed reason-code counts only (plus start/end/done/zero applied/false readiness); it never returns candidate rows or source identifiers. Add per-page counts for a full inspection summary. At end-of-input no new checkpoint is written. Validation failures return INSPECTION_VALIDATION_REJECTED; publication keeps the earlier rejected/uncertain error distinction. A decision allows up to 128 distinct reasons so complete validator blockers are not truncated; envelope/complexity limits still apply. No PHI is logged. This path intentionally repeats bounded prefix/dependency scans; it is not a certified large-dataset streaming importer.

### Offline source/target content reconciliation

An optional private `targets.contentSnapshot` now holds `{complete:true,tables:[entityType,...],rows:[{entityType,key:[primaryKeyPart,...],version,content:{...fullRow}}]}`. Entity types must exist in the local schema, tables must be unique/nonempty, and each row must belong to that declared scope. Keys are ordered nonempty tuples (up to six bounded strings/nonnegative safe integers); duplicate table/key pairs reject. Scalar and composite keys remain distinct; no key is inferred from contact or content. Version is a required explicit opaque string or NULL; absent/empty versions reject, and NULL preserves unavailable version evidence without inventing a timestamp. Content is a complete private JSON object, including unknown columns and absent/NULL/false/zero distinctions, under the existing secret/complexity/byte bounds. The contract validates representation, not correctness of primary-key extraction or completeness of columns/production census. A future trusted producer must establish those separately. No producer or cloud reader is enabled.

`await session.reconcileSnapshot(currentEncryptedSourcePath)` compares the session's baseline to a separately encrypted current source bundle, using the same private-file/key/format checks. Both require content snapshots with exactly the same declared table scope; missing/mismatched scopes fail with CONTENT_RECONCILIATION_REJECTED. Keyed canonical digests compare full source envelopes by source/path and target content by entity/key. Record/table/row enumeration order is irrelevant, but ordered keys and arrays inside content remain significant. Existing target identity metadata is compared separately. No private digest, key, row or content value is returned/logged.

The count-only report distinguishes source additions/removals/changes and target additions/removals/content/version changes. One changed target row counts as one conflict even if content AND version changed; identity-metadata drift adds one additional conflict. A version-only change is a conflict, and unchanged versions never hide changed content. Every comparison remains RECONCILIATION_ONLY with ATOMIC_VERSION_GUARD_PENDING and CENSUS_COMPLETENESS_PENDING; any unavailable target version adds TARGET_VERSION_EVIDENCE_MISSING. Even status unchanged means only equality of supplied snapshots, not freshness, backup validity, merge safety or apply authorization. No source/target is repaired, merged, deleted or overwritten.

## Important limits — do not hide them

The runner does not read real exports, stream an unbounded dataset, store checkpoints, apply SQL mutations, calculate private content checksums or rehearse a restore. These are the next Phase 4 tasks, not features implied by a successful report. In-memory lookup is bounded at 10,000 records, with pages up to 500 and a per-record complexity guard; it is not a production importer.

New-entity IDs use SHA-256 of JSON `["sood-clinic-migration-v1", entityKind, legacyId]`, first 16 bytes, with UUID version 8/variant bits. A fixed test vector prevents accidental algorithm changes. This is an application-specific deterministic ID, not a standard UUIDv5 implementation. For nested entities the eventual mapper must use the full qualified legacy path, not an ambiguous child ID alone. Existing SQL rows, including foundation catalogue rows, must reuse their already assigned IDs by unique `legacyId`; the pure mapper now reconciles supplied metadata but does not fetch live rows. Never overwrite existing IDs with newly derived UUIDs, and never infer authorization from identity reconciliation.

`mapCatalogRecord(record, records, targetSnapshot)` and `rehearse(records, {targetSnapshot})` accept a trusted in-memory identity snapshot: `{complete:true, branches:[{id,legacyId,code}], departments:[{id,legacyId,code,branchId}], doctors:[{id,legacyId,registrationNumber,branchId}]}`. Arrays are mandatory, metadata keys are allow-listed and the combined limit is 10,000. `legacyId:null` means unlinked; a unique code match with it is a conflict, not an adoption. The future protected reader may assert `complete:true` only after exhausting all bounded pages; setting it on a partial result defeats its purpose. Omitting the snapshot yields new-ID candidates only and does not check an actual target. Reusing an ID is not permission to overwrite newer target content.

The 13 normalized catalogue columns in schema source are currently local/emulator-only; production does NOT yet have them. All are nullable; sort order has a connector insertion default of zero, not an automatic backfill of old records. Do not apply the projections until a reviewed compatible cloud diff is applied/deployed and migration release gates pass. Missing optional scalar values map to NULL, while explicit empty strings and ordered memberships are preserved. A NULL or default zero membership order does not retroactively establish historical order. A private source envelope is not a substitute for SQL field preservation or a protected rollback snapshot.

The patient draft adds 11 nullable Patient columns and one `PatientReportedProfile` table locally (23 local tables versus 22 previously deployed). Health text is not in Patient demographics. No connector reads/writes the new table, and no runtime client uses it. Do not expose it to managers/admins or assume a patient-wide row establishes doctor ownership; later clinical access needs explicitly verified scope. Source author metadata is history, not an Auth role or verified audit actor.

`mapPatientRecord(record, records, snapshot)` optionally accepts `{complete:true, patients:[{id,legacyId,uhid}]}`; all metadata must be complete and bounded to 10,000. Snapshot absence means unchecked new-ID candidates, not an empty production database. No target-content overwrite/version policy is implemented. `patientTargetSnapshot` in fixtures is synthetic and exercises ID reuse in the CLI.

Missing createdAt remains NULL in the private candidate with `SOURCE_CREATED_AT_MISSING`, rather than inventing creation time for the required SQL column. Empty DOB maps to NULL with an explicit representation-review blocker. Nanosecond precision, account ownership, derived search keys and the patient cutover remain blocked. Raw source shape is retained privately; it is not permission to apply an incomplete row. No future apply path may ignore blockers just because status is `mapped`. Real patient export/import and backup/restore gates are unchanged.

These utilities are not yet a complete validator for deferred clinical/appointment entities.
